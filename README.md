# Paddy Doctor: классификация болезней листьев риса

Мы разрабатываем систему, которая по фотографии листа риса определяет одну из девяти болезней или класс `normal`.

Источник данных — [соревнование Paddy Doctor на Kaggle](https://www.kaggle.com/competitions/paddy-disease-classification/overview). В датасете 10 407 размеченных обучающих и 3 469 тестовых изображений. В `train.csv` указаны `image_id`, `label`, сорт риса `variety` и возраст `age`; изображения лежат в `train_images/<label>/` и `test_images/`. На Kaggle качество измеряется accuracy. В проекте мы также планируем считать macro F1, balanced accuracy, recall по классам и матрицу ошибок, поскольку классы представлены неравномерно.

## Setup

Нужны Python 3.11–3.13, [uv](https://docs.astral.sh/uv/getting-started/installation/), Git и учётная запись Kaggle с принятыми правилами соревнования. Из корня проекта:

```bash
uv sync --frozen
uv run pre-commit install
uv run pre-commit run -a
```

Зависимости заданы в `pyproject.toml` и закреплены в `uv.lock`. Новую используемую библиотеку добавляйте через `uv add <имя>` или `uv add --dev <имя>`; вместе с изменением `pyproject.toml` обновляйте `uv.lock`. Не добавляйте пакеты «на будущее».

### Данные и DVC

Исходные данные не коммитятся в Git. В репозитории остаются только файлы `*.dvc` с закреплёнными версиями данных. Каждый участник скачивает набор данных с Kaggle и использует **своё локальное DVC-хранилище** `.dvc/local-remote/`; оно исключено из Git и не копируется коллегам.

После `uv sync --frozen` можно автоматически скачать данные и заполнить локальное DVC-хранилище:

```bash
uv run kaggle auth login
uv run python -c 'from paddy_doctor.data import download_data; download_data()'
uv run dvc pull
```

Если данные уже скачаны вручную, распакуйте их в корень проекта в структуре ниже и выполните только вторую и третью команды. `download_data()` увидит существующие файлы, проверит состав датасета и добавит их в локальный DVC cache и remote без повторного скачивания. Также можно передать путь к скачанному ZIP-архиву через аргумент `archive` функции. При загрузке через CLI могут потребоваться вход в Kaggle и принятие правил соревнования.

Код обучения и инференса должен перед чтением данных вызывать `paddy_doctor.data.ensure_data("train")` или `paddy_doctor.data.ensure_data("infer")`. Функция вызывает DVC pull; если локальное хранилище ещё пусто, она запускает загрузку с Kaggle и заполняет его. Егор и Арина подключают этот вызов в свои команды.

**Ограничение выбранной схемы:** из чистого клона один лишь `dvc pull` не скачает данные, пока локальное хранилище не заполнено через `download_data()`. Это следует из того, что общее DVC-хранилище мы не используем.

Структура датасета:

```text
train.csv
sample_submission.csv
train_images/<label>/<image_id>.jpg
test_images/<image_id>.jpg
```

Тестовый набор не содержит меток. Для локальной оценки используйте только размеченный `train.csv`, сохраняя разбиение и seed эксперимента. Не используйте тестовый набор Kaggle для выбора гиперпараметров по публичному leaderboard.

## Правила работы с репозиторием

- Рабочую версию сдаём в основной ветке `main` или `master`; проверяющий использует именно её.
- Не добавляем в Git изображения, CSV с данными и предсказаниями, checkpoint, ONNX/TensorRT-файлы, DVC cache, локальные секреты и `.venv`.
- Перед передачей изменений запускаем `uv run pre-commit run -a` и проверяем инструкцию из чистого окружения.
- Название Python-пакета — `paddy_doctor`; файлы и функции называем в `snake_case`.
- В коде не отключаем предупреждения глобально и не выполняем работу при импорте модуля.
